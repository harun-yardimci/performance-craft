SwiftUI: work inside body

Before
var body: some View { let f = DateFormatter() if let img = UIImage(data: photo.data) { Image(uiImage: img) } }
After
static let parser: DateFormatter = { … }() @State private var headerImage: UIImage? // decoded once in init, reused by body

body runs on every state change. A slider that changes portion size re-decoded a full-size photo on each step.

Rule: formatter-in-body · confirm with the SwiftUI instrument

Long lists that render every row

Before
ScrollView { VStack { ForEach(meals) { MealRow($0) } } } Column(Modifier.verticalScroll(state)) { meals.forEach { MealRow(it) } }
After
ScrollView { LazyVStack { ForEach(meals) { MealRow($0) } } } LazyColumn { items(meals, key = { it.id }) { MealRow(it) } }

Fine for ten rows, a hang for a thousand. The skill only flags lists that grow with user data.

Rules: list-not-virtualized, list-key

Android release build

Before
release { isMinifyEnabled = true // no isShrinkResources // no Baseline Profile }
After
release { isMinifyEnabled = true isShrinkResources = true // + res/raw/keep.xml } plugins { id("androidx.baselineprofile") }

Resources looked up by name (getIdentifier) must be listed in keep.xml, or the shrinker removes them. Baseline Profiles precompile startup code.

Rules: resources-not-shrunk, no-baseline-profile
