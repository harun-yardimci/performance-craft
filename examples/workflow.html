1Frame

What is slow, for whom, on which device and network. Pick the metric that matches the complaint.

2Baseline

Measure before touching code: perf_audit.mjs, static scan, platform profilers, endpoint timing.

3Diagnose

Symptom → cause (file:line, request, query) → fix → expected effect, from metric breakdowns.

4Prioritize

Impact × confidence ÷ effort. “High on sight” items first.

5Fix

The cheapest change that solves the measured problem, keeping behavior identical.

6Verify

Same command, same conditions, medians and spread. Nothing else may regress.

Cheapest fix first

Delete work→Do it less often→Later or elsewhere→Faster→More hardware

Unused code and duplicate requests go before caching; caching before rewrites; rewrites before bigger servers.

Priority order

  1. Failures: timeouts, hangs, ANRs, OOM, endpoints that fall over
  2. The metric the user complained about; vitals in “poor”
  3. Systemic waste: N+1, unbounded queries, no caching, heavy JS
  4. Micro-optimizations, only when a profile shows them hot
