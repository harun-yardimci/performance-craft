Before
2.40 s 12 clients × (round + photos), one after another
for client in selected { let round = try await fetchRound(client.id) let photos = try? await fetchPhotos(client.id) … }
  • 124 independent requests wait for each other. With real ~330 ms API calls that is about 8 s before the feed appears.
After
0.32 s 4 clients at a time, round and photos together
await withTaskGroup(of: (Int, Result).self) { group in for (i, id) in ids.enumerated() { if i >= 4, let done = await group.next() { keep(done) } group.addTask { (i, await fetchRoundAndPhotos(id)) } } // results kept in client order }
  • 1A concurrency cap of 4 respects the API; results are processed in the original order, so error and cancellation rules don't change.

Found by static_perf_audit.py (query-in-loop) in a real SwiftUI + Compose app. Timings measured in a Swift 6 harness with 100 ms mock requests (peak concurrency 4, order kept, one failure isolated). On-device timing not verified.
